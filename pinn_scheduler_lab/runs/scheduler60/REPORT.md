## E 的行为检查

- heat2d：动作切换 19 次；BC / PDE / Joint 分别占实际优化秒的 4.8% / 4.1% / 91.1%。PDE 检查段中最大 e_bc=2.108（目标 τbc=0.03）。
- ns2d：动作切换 95 次；BC / PDE / Joint 分别占实际优化秒的 37.1% / 45.5% / 17.4%。PDE 检查段中最大 e_bc=0.2649（目标 τbc=0.03）。

这些是检查点观测到的峰值，不能当成逐步最大值。阈值是触发规则，不是硬约束：PDE 更新可能在两次检查之间显著破坏边界；最小驻留还可能延迟恢复。大量时间最终落在 Joint 时，不能把精度改进归因于长期的纯 PDE 学习。

## 开销是否值得

- heat2d：E 规则计算 0.00133s，全部物理诊断 1.726s；A 相应诊断 1.568s。规则计算很便宜，但状态信息不是免费的；按步数检查还使不同方案诊断次数不同。应将两列一起考虑。
- ns2d：E 规则计算 0.00157s，全部物理诊断 2.912s；A 相应诊断 1.530s。规则计算很便宜，但状态信息不是免费的；按步数检查还使不同方案诊断次数不同。应将两列一起考虑。

本版所有方法均带同样诊断，没有另外运行免诊断 A，因此不能声称已经准确测出部署时 E 相对最轻量 A 的全部增量开销。

## 公平性与限制

- 每个 PDE/种子内，A–E 初始权重与采样 SHA256 相同；Adam 状态跨阶段连续保留。各方法最后步数可以不同，BC 单步成本较低。
- 计费秒 = 优化耗时 + 固定检查耗时 + 策略耗时。所有方法每 50 步接受相同探针和梯度冲突诊断；D 额外逐步更新权重。解析网格和最终审计不进入控制状态，评估时间单列。计费时间不是训练循环墙钟时间（不含初始化、初始保存和最终 JSON/图表生成）；后者包含 Python 调度、评估及保存。
- 最后一步及最终诊断允许少量预算超时。曲线采用实际计费时间；没有按真解误差早停或挑选最优检查点。
- 单种子是流程验证，不支持显著性推断。B/C 只用了等时间三阶段，尚未精调分段；E 即使领先也不能证明优于最优手工阶段。
- 阈值与迟滞、最小驻留是人为选择。未做阈值、K、Re、网络或高频/瞬态问题的消融。没有新增控制器网络，也没有训练学习策略。
- 当前研究对象是稳态、单位方域和 Re=20 的解析解问题；不据此推断复杂真实流动表现。
- 先运行 A 基线门槛（热/速度 <5%、压力 <10%），通过后冻结设置，才运行 B–E。30 秒预试压力未过门槛，因此全组统一采用 60 秒。试验选择过程完整保留在 pilot30、pilot60，不隐藏负结果。
